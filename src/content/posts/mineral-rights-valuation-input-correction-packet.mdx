> **Educational correction-intake boundary.** This article provides an administrative template for recording an already-identified factual input discrepancy. It does not validate a source, reperform or revise a valuation, calculate value, establish title, ownership, acreage, royalty decimal, property identity, legal effect, document sufficiency, appraisal, offer fairness, buyer quality, tax treatment, or whether to sign, sell, or hold. Use qualified title, land, legal, tax, accounting, appraisal, engineering, and financial professionals for owner-specific conclusions. MRX may have an economic interest in a later transaction; when that applies, the buyer relationship is disclosed in writing before an agreement is signed.

A mineral rights valuation input correction packet is a routing record, not a new valuation. It begins after an owner or reviewer has already identified one concrete factual input discrepancy. The packet preserves what the reviewed output displayed, points to the source location, states the replacement being requested, and records where the request sits in the intake process.

The allowed statuses are deliberately narrow: **received**, **source linked**, **clarification requested**, **accepted for review**, **not accepted for review**, or **unresolved**. None of them means that an input was changed, a calculation was rerun, or a valuation range moved.

## Keep discovery, intake, and valuation separate

Three different jobs can look similar if they share one spreadsheet.

1. **Validation and reperformance** ask whether evidence, transformations, assumptions, and methods can be traced and repeated. The [valuation-validation guide](/blog/understanding-mineral-rights-how-to-validate-your-asset-s-true-worth/) owns that job.
2. **Correction intake** records a discrepancy that has already been identified and routes a requested replacement. That is the job of this packet.
3. **Valuation revision** decides whether to accept a source, replace an input, rerun an analysis, and issue a changed output. That requires the reviewer or qualified professional responsible for the analysis.

Do not use a correction packet to discover every possible error in a valuation. Do not use it to compare methods, choose assumptions, run sensitivities, or argue for a target result. If the discrepancy is not yet specific, return to validation or ask the reviewer what evidence is needed.

## Freeze the reviewed snapshot

Preserve the exact valuation or directional review version in which the discrepancy was observed. Record its visible date, version or file name, page or section, and controlled storage location. Do not overwrite that source file with a corrected copy.

The [Texas valuation-process guide](/blog/understanding-texas-mineral-rights-valuation-process/) explains why a useful review keeps the analyzed interest, evidence, inputs, assumptions, range, and unresolved questions traceable. The correction packet does not repeat that workflow. It simply pins the request to the output actually reviewed.

The National Archives [Records Basics](https://www.archives.gov/records-mgmt/scheduling/basics) page is federal-agency guidance, not a private mineral-owner retention rule. Its distinction among source records, input records, system content, and outputs is still a useful analogy: the document that supplied an input, the value entered into an analysis, and the report produced from it are related but not interchangeable.

## Assign one correction-request ID per discrepancy

Give each discrepancy a stable ID such as `VCR-2026-001`. One row should address one input field in one reviewed snapshot. If three different fields may be wrong, create three linked requests rather than combining them into one broad complaint.

This keeps status language precise. A reviewer might request clarification for one field, accept another for review, and leave a third unresolved. Combining them would make the status ambiguous and could incorrectly imply that every requested replacement moved together.

## Record the observed input without endorsing it

For each request, record only what can be pointed to:

- **Correction-request ID:** a unique internal identifier;
- **Reviewed snapshot:** file name, version, date, or controlled record ID;
- **Field name:** the exact label or a neutral description of the input location;
- **Observed value:** what the reviewed snapshot displays, including units when shown;
- **Snapshot location:** page, section, worksheet, cell, or screen label when available;
- **Source reference:** the retained document or record that prompted the request;
- **Source location:** page, exhibit, statement line, or controlled record pointer;
- **Requested replacement:** the value or description the owner asks the reviewer to consider;
- **Stated reason:** a short factual explanation of the mismatch;
- **Requested by and date:** the person routing the request and the observed submission date; and
- **Intake status:** one of the six allowed workflow statuses.

The packet may say, for example, that a reviewed worksheet displays one decimal while a retained division-order page displays another. It may not decide which decimal is legally correct, whether the division order controls, who owns the interest, or what the valuation would be if a replacement were used.

## Link support without rebuilding the document package

Use the separate [sale document-package index](/blog/how-to-build-a-mineral-rights-sale-document-package-index/) to preserve file identity, pages, exhibits, versions, and replacements. The correction packet should link to that stable component ID and exact page rather than copying an entire sensitive document into every request row.

Record **source linked** only when the request points to a controlled source location. The status does not mean that the source is authentic, complete, legally effective, or sufficient for the requested correction.

If no supporting record is available, write **not available** in the source-location field and use **clarification requested** or **unresolved** as appropriate. Do not fill a gap from memory.

## Use the federal correction process only as an analogy

The EPA [Information Quality Guidelines page](https://www.epa.gov/quality/epa-information-quality-guidelines) describes a federal mechanism for requesting correction of information disseminated by EPA. Section 8.2 of the linked [EPA guideline PDF](https://www.epa.gov/sites/production/files/2020-02/documents/epa-info-quality-guidelines_pdf_version.pdf) calls for identifying the requester, describing the disputed information with specific citations, explaining the concern, recommending corrective action, and describing how the alleged error affects the requester.

Those federal rules do not govern a private mineral-rights valuation or create a right to a revised result. The useful analogy is narrower: identify the exact information, point to where it appears, state what is requested, and supply the relevant support. This article intentionally omits the EPA process's legal and agency-specific standards.

## Apply controlled intake statuses

Every request ends in one of these workflow statuses:

1. **Received:** The packet reached the designated intake point.
2. **Source linked:** The request points to a controlled supporting record and location.
3. **Clarification requested:** The reviewer asked for a clearer field, source, location, unit, or requested replacement.
4. **Accepted for review:** The request may be considered by the responsible reviewer.
5. **Not accepted for review:** The request will not enter that review path, with a stated intake reason when available.
6. **Unresolved:** The available record does not support a complete intake disposition.

Add the same note beside every status definition: **This status does not mean the valuation changed.** In particular, accepted for review is not accepted as correct, and not accepted for review is not proof that the original input is correct.

## Separate a reviewed outcome from a changed output

If a responsible reviewer later replaces an input and issues a new analysis, record that event outside the correction packet or in a linked revision register. Preserve the prior snapshot, the new snapshot, the responsible reviewer, the changed field, and the date.

Do not update the correction request's observed-value field to match the new output. That field documents what prompted the request. Overwriting it would erase the trail between the original observation, the requested replacement, the review disposition, and any later revision.

The correction packet may link to a new version. It may not say that the new value is certified, legally correct, fair, or appropriate for a sale unless a qualified professional separately reaches and documents that conclusion.

## Protect sensitive records

Valuation materials can contain names, addresses, legal descriptions, account identifiers, production data, royalty decimals, tax information, and signatures. Keep the packet minimal. Store sensitive source records in a controlled location and link to a restricted component ID.

Do not place passwords, one-time links, bank information, taxpayer identifiers, complete account numbers, or unnecessary personal data in an ordinary shared worksheet. Record access restrictions and give the packet only to people authorized to review the matter.

## Example of a bounded request

Suppose an owner notices that a directional review worksheet displays a royalty-decimal input that differs from a decimal displayed on a retained statement.

The packet can record:

- reviewed snapshot and field location;
- observed worksheet value, exactly as displayed;
- statement component ID and line location;
- requested replacement, exactly as stated by the owner;
- reason: displayed values differ;
- status: source linked; and
- note: status does not mean the valuation changed.

The packet cannot decide which decimal is correct, whether the statement is authoritative, whether title supports the interest, how the range would move, or whether an offer is fair. Those conclusions remain with qualified reviewers.

## Final quality check

Before routing a packet, confirm that:

- each row covers one specific discrepancy;
- the reviewed snapshot is preserved and identified;
- the observed field and value are transcribed without alteration;
- the source link points to a controlled record and exact location when available;
- the requested replacement is labeled as a request, not a verified fact;
- the stated reason is factual and short;
- the status uses only the controlled vocabulary;
- every status carries the no-change note; and
- the packet contains no valuation, title, ownership, acreage, fairness, appraisal, tax, buyer, negotiation, or sell-or-hold conclusion.

A good correction packet makes the next review step traceable without pretending to resolve it. If the question is “Which field, source, and replacement is being requested?” the packet can answer. If the question is “Which value is legally or economically correct, and what does that do to value?” stop and route the source records to the qualified professional responsible for that conclusion.
