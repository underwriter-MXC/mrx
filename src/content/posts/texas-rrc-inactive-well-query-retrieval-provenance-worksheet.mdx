> **Public-record retrieval boundary.** This article records one Texas RRC Inactive Well Query attempt. It does not interpret a result, operator, API number, district, lease, well type, county, field, date, link, document, or source limitation. It does not establish property connection, title, ownership, acreage, tract or unit inclusion, lease effect, payee status, royalty share, decimal, payment responsibility, entitlement, compliance, environmental condition, operating status, production, cash flow, value, price, offer quality, or a transaction result. It does not provide legal, title, land, tax, accounting, appraisal, engineering, geological, reserve, environmental, or financial advice. MRX may have an economic interest in a later transaction; when that applies, the buyer relationship is disclosed in writing before an agreement is signed.

A **Texas RRC Inactive Well query retrieval** worksheet answers one narrow question: exactly how was one official Inactive Well Query attempted? Record the entry route, source-displayed criteria, navigation steps, result-header state, result locator, access timestamp, source limitation, retained reference, and one bounded retrieval status.

Use only `located`, `not located`, or `unverified`. Those terms describe the query attempt. They do not decide whether a well is inactive, connect any record to private property, or determine a lease, status, payment, compliance, value, or transaction outcome.

## Start with the named official route

The Railroad Commission of Texas [Research Queries](https://www.rrc.texas.gov/resource-center/research/research-queries/) directory lists **Inactive Well Query** as a named Oil & Gas route. Preserve the full directory address and the complete [Inactive Well Query](https://webapps2.rrc.texas.gov/EWA/inactiveWellAllQueryAction.do) address instead of recording a generic phrase such as `RRC inactive-well search`.

The RRC’s Oil & Gas Data Query menu treats this query as separate from production, wellbore, injection-storage, severance, proration, organization, P-4, orphan-well, drilling-permit, inspection, and violation routes. This worksheet owns one bounded **Inactive Well Query** attempt. It does not merge those other routes or turn a route name, screen label, or displayed result into a conclusion.

The RRC directory says its online research queries are intended for people needing specific information and warns that automated retrieval of volumes of data can degrade its systems. It also describes the online query material as informational. Record the source limitation and access time. Do not treat a screen, result list, or retrieval attempt as authoritative legal, title, regulatory, environmental, or transaction evidence.

For broad orientation, use [Texas Railroad Commission: How to Use Public Records to Understand Your Mineral Rights](/blog/texas-railroad-commission-how-to-use-public-records-to-understand-your-mineral-rights/). This page owns the smaller reproducibility record for one query attempt.

## Create an attempt header before searching

Give the attempt a neutral ID such as `TX-IWQ-RET-01`. The ID labels a query session, not a property, well, operator, or transaction conclusion.

Record these fields before entering criteria:

- **Attempt ID:** a stable internal label;
- **Purpose:** `public Inactive Well Query retrieval only`;
- **Official entry route:** the complete addresses opened;
- **Query-page label:** copied exactly as displayed;
- **Access date and time:** when the criteria screen was viewed;
- **Timezone:** attached to that timestamp;
- **Prepared by:** a role or controlled identifier;
- **Worksheet version:** the version used for this attempt; and
- **Source limitation:** the source’s stated coverage, update, access, or display note.

Create a new attempt for a rerun. Do not overwrite a prior criteria snapshot or result state merely because the page, date, or displayed data changed.

## Capture each used criterion by its displayed label

The current [Inactive Well Query](https://webapps2.rrc.texas.gov/EWA/inactiveWellAllQueryAction.do) screen labels fields including **Operator No.**, **API Unique No.**, **Oil Wells**, **Gas Wells**, **Both**, **District**, **Oil Lease No./Gas Well ID No.**, **Type Well**, **County**, and **Field(s)**. The [official How To help](https://webapps2.rrc.texas.gov/EWA/help/InactiveWellQuery_HowTo.htm) describes an operator search plus other criteria and separate lease and field search steps. Preserve the exact screen wording shown at the time of the attempt instead of relying on memory.

Each criterion is a locator field, not a conclusion. Create one row for every field used:

- **Criterion label:** copied as displayed;
- **Entry method:** typed value, selected option, linked lookup, or left unused;
- **Controlled value reference:** the entered or selected value stored appropriately;
- **Format shown by source:** option label or instruction;
- **Used in submission:** `yes` or `no`; and
- **Capture note:** any displayed constraint, default, or warning that affected the attempt.

If a control was not used, record `unused`. Do not replace individual labels with a vague statement such as `searched inactive wells`. Do not publish real identifier values in a reusable example.

## Record the submission and navigation path

After submitting criteria, preserve only the route that actually occurred. A bounded path can look like:

`official directory → Inactive Well Query → criteria submitted → result list → displayed link or next route`

For each step, record:

- the displayed page or link label;
- the route or controlled route reference;
- the action taken;
- the access time and timezone;
- whether the page loaded, changed, timed out, or showed no rows; and
- the next step actually selected.

Do not reconstruct a sequence from memory. If the session ended, an error appeared, or a stated constraint prevented submission, preserve that event and use `not located` or `unverified` for the narrow retrieval fact.

## Keep result state and downstream meaning separate

The [Inactive Well Query results help](https://webapps2.rrc.texas.gov/EWA/help/InactiveWellQuery_results_howto.htm) provides bounded result-screen context. That identifies a navigation pattern; it does not establish the meaning, accuracy, completeness, legal effect, operating condition, or property connection of an individual result.

Record the result state separately from individual rows:

- **Criteria echoed by the result page:** exact labels and controlled values;
- **Displayed result range or count:** copied as shown, if present;
- **Displayed sort, page, and page-size state:** only when displayed or used;
- **Result-page access time:** with timezone; and
- **Result-page message or limitation:** copied or accurately paraphrased.

Then preserve only labels actually observed. A row may contain a displayed operator, API number, district, lease, well type, county, field, date, or link label. Keep each label attached to its value and use `not displayed` when the source does not show a field. Matching text or numbers are not a property connection.

## Treat every new route as a new retrieval step

If a result exposes a detail link, blank document, help page, or another official record channel, create a separate step with:

- originating attempt ID and result reference;
- displayed link or tab label;
- destination route or controlled reference;
- destination page label;
- new record class or fields displayed;
- access timestamp and timezone;
- retained reference location; and
- `located`, `not located`, or `unverified`.

The **Inactive Well Query** screen is not the same as a Wellbore Query, H-10 Query, Organization Query, P-4 Query, production query, injection-storage query, drilling-permit query, or a lease-clause review. Do not combine a result from any of those routes into one implied operational, regulatory, property, or transaction record.

The [Texas RRC Wellbore Query Retrieval Provenance Worksheet](/blog/texas-rrc-wellbore-query-retrieval-provenance-worksheet/) owns a different wellbore route. The [Texas RRC H-10 Query Retrieval Provenance Worksheet](/blog/texas-rrc-h-10-query-retrieval-provenance-worksheet/) owns a different H-10 route. Preserve those boundaries even when screens display an operator, lease, or number.

## Use only bounded retrieval statuses

Keep the status vocabulary deliberately small:

- **Located:** the recorded official query exposed an identified result reference.
- **Not located:** the recorded attempt did not expose the sought result.
- **Unverified:** a label, identifier, route, or result appeared, but the narrow retrieval fact or relationship was not established.

`Located` does not mean connected, applicable, complete, accurate, current, active, inactive, compliant, permitted, productive, paid, valuable, or legally effective. `Not located` does not mean nonexistent. `Unverified` preserves uncertainty without alleging an error or defect.

Turn gaps into neutral retrieval questions:

- Which criterion or displayed limitation narrowed this attempt?
- Did the result header echo every criterion as entered?
- Did the screen state any coverage, update, or display limit?
- Which result page and sort state were examined?
- Does the result expose a separate official route or controlled record channel?
- Which official source can describe the requested record class without converting it into a property conclusion?

## Preserve an authorized retained reference

The live query and a retained object are different evidence. For every authorized screenshot, export, or file, record:

- attempt ID;
- official route and navigation path;
- criteria snapshot;
- result-header and display state;
- result-row or next-route reference;
- access timestamp and timezone;
- controlled storage location;
- file hash when your records process uses one; and
- handling note for identifiers, names, well data, legal descriptions, account data, or other sensitive information.

Do not publish an actual query result, operator number, API number, lease number, or property-specific record in a reusable worksheet. A controlled reference proves only what was retained for the recorded attempt.

## Final quality check

Before closing the worksheet, confirm that:

- the exact official directory and Inactive Well Query routes are named;
- every submitted criterion retains its source label and controlled value;
- any instruction, default, or limitation is captured as shown;
- the navigation path records only steps that occurred;
- result headers, rows, detail links, and other query routes remain separate;
- the access timestamp, source limitation, and retained reference are attached;
- every status is only located, not located, or unverified;
- no row interprets a result, identifier, well type, status, date, link, operator, or property relationship; and
- no row establishes title, ownership, acreage, unit inclusion, lease effect, payee status, payment responsibility, compliance, environmental condition, operating status, production, value, price, offer quality, or a transaction result.

A strong provenance worksheet is narrow by design. It lets an authorized reviewer understand and repeat the recorded Inactive Well Query attempt. It does not decide what any result means.
